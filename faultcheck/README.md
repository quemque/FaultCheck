# Отчёт по модели прогнозирования отказов оборудования

## 1. Задача

Бинарная классификация: предсказать вероятность отказа станка (`machine_failure`) по показаниям датчиков. Датасет сильно несбалансирован (поломки ≈3% случаев), поэтому основная метрика — **PR-AUC**, а не accuracy.

## 2. Данные и препроцессинг

- Схема данных жёстко задана через `pl.Schema` — все типы колонок проверяются при чтении.
- Названия колонок нормализуются (нижний регистр, пробелы → `_`, убираются скобки) — защита от разного формата заголовков в CSV.
- Из признаков **исключены** `udi`, `product_id` (идентификаторы, не несут физического смысла) и все колонки конкретных типов поломок (`twf, hdf, pwf, osf, rnf`) — иначе была бы утечка целевой переменной.
- Категориальный `type` кодируется через `LabelEncoder` (L=0, M=1, H=2), маппинг переносится в polars через `replace_strict`.

## 3. Инженерия признаков

Добавлены два физически осмысленных признака:

- `temp_diff = process_temperature − air_temperature` — косвенно отражает нагрузку/тепловыделение;
- `power = rotational_speed × torque` — механическая мощность, ключевой индикатор перегрузки.

Это даёт модели нелинейные взаимодействия «из коробки», без ручного перебора.

## 4. Разделение выборки

`train_test_split` со `stratify=y` — сохраняет долю поломок в train и test одинаковой, что критично при дисбалансе. `random_state=42` — воспроизводимость.

## 5. Модель

`XGBClassifier` (градиентный бустинг над решающими деревьями):

- `n_estimators=150`, `learning_rate=0.03`, `max_depth=5` — умеренная сложность, чтобы не переобучиться на редком классе;
- `scale_pos_weight = N_neg / N_pos` — компенсирует дисбаланс, заставляя модель сильнее штрафовать пропуск поломок;
- `eval_metric="logloss"` — корректная функция потерь для вероятностного выхода.

На выходе берётся `predict_proba[:, 1]` — калиброванная вероятность отказа, а не жёсткий класс.

## 6. Оценка качества

- **ROC-AUC** — насколько хорошо модель ранжирует примеры;
- **PR-AUC (Average Precision)** — основная метрика при дисбалансе, показывает качество именно по редкому положительному классу.

## 7. Сохранение

Модель сохраняется в `model.ubjson` (UBJSON — компактный бинарный JSON, родной формат XGBoost) по запросу пользователя.

## Итог

Пайплайн: **чистые данные → физические фичи → стратифицированное разбиение → XGBoost с балансировкой классов → оценка по PR-AUC**. Такой подход стандартен для задач промышленной диагностики и обоснован особенностями датасета (дисбаланс + физический смысл признаков).
